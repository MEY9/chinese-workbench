# 教材 PDF 接入规范 v1

> 2026-10-23 用户补充：开发完成后提供小学语文一至六年级、不同出版社的教材 PDF。本规范先固定接入与校对规则，不假设文件现已存在。

## 目录模型

一本教材由 `publisher`（出版社或教材系列）、`grade`（1–6）、`term`（上/下册）、`editionYear`（版本年份或修订版）、`title` 唯一标识；目录项另有稳定 `bookId`、原文件名、相对路径、文件字节数与 SHA-256。出版商字段按 PDF 版权页原文填写，不预设“所有出版社”的封闭名单。相同出版社、年级、册别若年份不同，作为独立教材。

建议包结构：

```text
app/
  index.html
  textbooks/
    <bookId>.pdf
  textbooks-manifest.json    # 构建输入；目录内容编入 index.html
```

教材包需要跟随 `index.html` 一起移动；入口 HTML 本身仍无 CDN 或运行时依赖。文件名用稳定 ASCII `bookId`，中文书名等留在目录元数据中。用户在提供 PDF 后可用构建脚本校验文件是否存在、计算哈希、将清单编入 HTML；打开本机 PDF 使用相对链接，不主动联网。

## 当前阶段与后续接入

当前 R1 可创建目录元数据和班级绑定，未提供的 PDF 一律显示“待导入”；教师可临时选择本机文件预览，但不声称已经永久保存。拿到文件后，逐本按 `app/textbooks/entry.example.json` 建立 UTF-8 元数据文件，运行 `python app/register_textbook.py --metadata 元数据文件.json`。脚本校验 PDF 头、复制文件并计算 SHA-256；构建脚本再次校验哈希。元数据可填 `pageCount` 与 `lessons`：每课记录课次编号、标题、PDF 起止页、校对人和日期；未核对时保持空数组，界面明确显示“待人工校对”，核对后才显示可跳转的课次目录。仍需人工检验 PDF 确实可打开、页数和页码准确。教材文字/拼音不能由 PDF 文件名或 AI 自动推断为已校对词库。已有教师自建同元数据目录项在新 PDF 包进入时会按出版社/年级/册别/版次绑定到正式文件，保留原教学记录。

G2 材料至少包含每本 PDF 的 `bookId`、文件 SHA-256、元数据核对人/日期、页数和课次映射核对表。若只收到部分出版社或册别，只声明实际已接入的范围；目录能力可支持更多，不等于内容已经齐全。
