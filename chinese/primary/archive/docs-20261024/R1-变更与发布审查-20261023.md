## 数据架构核对

用户已明确要求使用 SQLite，原“需重新评审、不能替换”的结论撤销，以最新授权为准。

- 业务数据全部经本机 Python 服务写入 `app/data/workbench.sqlite3`。按集合分表、班级外键、同事务保存；保留最近 20 次历史状态。
- SQLite WAL、FULL 同步、事务回滚、版本冲突拒绝和请求标识去重已实现。旧浏览器数据只读导出，禁止备用写入。
- 前端仍整份状态提交，适用于本机单教师；尚未改为增量实体接口。
- JSON 是独立业务备份，教材 PDF 仍为独立文件。真实用户旧数据未自动迁移，需原浏览器导出后导入。
- 运行、恢复、接口范围与实际限制见 [SQLite 说明](../SQLite运行与迁移说明.md)。
- 当前无 Git 元数据，不能提供提交级回退证据。

## 发布结论与待办

**当前仅为可测试原型，R1 正式交付不通过。** 以下证据缺失时，不得把测试通过写成产品可用或正式交付：

1. G2：12 册 PDF 的版权页、页数、课次页码和词库人工核对；真实浏览器旧数据迁移及备份恢复；存储异常恢复。
2. G3：两班各 50 人、20 周数据的全链路演练，逐条对应 F01–F11、F13 的验收条件，P0/P1 缺陷清零。
3. G4：Edge 和 Chrome 的本机 HTTP 工作流、旧 `file://` 迁移、断互联网但保留本机服务的网络面板、A4 打印、中文语音降级、键盘与 200% 缩放实测。
4. G5：至少两位小学语文教师各连续五个工作日，用脱敏数据独立试用并关闭关键阻碍。

后续开发先记录需求编号、变更原因、风险、回归用例和门禁归属；优先修复门禁阻塞问题。未经这些证据，不继续扩展功能范围。
