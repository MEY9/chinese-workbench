## 开屏问题最终根治:v2.4.0(2026-10-24,用户第三次报告;授权清空数据)

| 项 | 内容 |
|---|---|
| 真正根因(v2.3.3 才暴露) | Electron `contextIsolation` 下 preload 运行在隔离世界——向 `window` 注入的 `__API_BASE` 页面脚本**永远看不到**;此前所有"注入+轮询等待"方案从原理上无效(错误消息停留在 file:// 拒绝即证明)。这属于我对 Electron 安全模型的理解失误 |
| 最终架构 | **桌面模式弃用整个 HTTP 存储层**:`requestJSON` 顶部判断桌面桥存在即直走 `ipcRequest`(Electron IPC 进程通信),无端口、无监听、无注入、无竞态;内嵌 HTTP 服务/启动参数/注入代码全部删除;单实例锁保留 |
| 兼容 | 纯浏览器 file:// 旧版仍走原拒绝分支;HTTP 路径保留给浏览器开发预览 |
| 验证 | 真实启动:内嵌 API 日志 0 条(已移除)、迁移/恢复页 0 次、业务错误 0 次;R1 回归全绿 |
| 交付 | v2.4.0 安装包(Windows);v2.2.0–2.3.3 旧包清理 |
| 教训 | 跨进程数据传递必须走框架官方通道(contextBridge),不要往 window 上挂变量;每轮修复后必须在**打包版**(非 dev)上做页面级验证 |

## 开屏问题最终修复:v2.4.1(2026-10-24,打包版实机验证)
