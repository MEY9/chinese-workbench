# 语文教师工作台开发复核

复核日期：2026-10-25。依据：当前有效 PRD、变更记录、app/src 源码、Electron 主进程及渲染入口、隔离数据验证。

## 结论

功能范围已覆盖班级、教学、课堂、听写/作业人工记录、成绩、学生档案、打印、教材和 AI 辅助；存在 Electron 3.0.0 安装包，桌面数据层实际使用 better-sqlite3。已具备功能较完整的试用版本基础。

但目前不能判定为可交付版本。发现会影响统计准确性、多班级隔离、数据恢复和隐私承诺的缺陷。应先完成以下修复，再推进发布验收。

本次只新增复核报告和两个独立探针脚本，没有修改产品源码、生成页面、安装包或已有业务记录。为检查页面启动了已有本机服务。内置浏览器导航被 URL 策略阻断，且此前页面显示连接失败，因此未完成最新版 UI 的视觉和真实交互验收。下面的结论来自代码及隔离验证，不等同于桌面安装包全流程验收。

## 优先修复项

### R1 · P1 · 未录入成绩被当作零分

- 位置：`app/src/app.js:498`，`saveGrades` 位于 749 行。
- `saveGrades` 给所有学生保存 score 字符串；`gradeStats` 对空字符串执行 Number，结果为 0。
- 复现：两名学生分别为 100 分和空白，得到平均分 50、最低分 0、及格率 50%、统计人数 2。
- 影响：成绩分析和发送给 AI 的统计都可能错误；缺考、未录与真实零分无法区分。
- 验收：100 分加空白应得到已录人数 1、均分 100；100 分加真实 0 分应得到人数 2、均分 50；缺考状态单列；非法及超范围值禁止保存。

### R2 · P1 · 积分与座位表没有按班级隔离

- 位置：`app/src/app.js:479`、488、773、781。
- 积分以 `state.points[学号]` 保存，多个班级的同号学生共享积分。座位使用一个全局 `state.seats` 数组。
- 复现：甲班 01 号积 1 分，乙班 01 号也显示 1 分；甲班排过座位后切换乙班，座位渲染为空，因为仍在查找甲班学生 ID。
- 验收：至少两个班、相同学号、不同人数，分别加减分和换座，切班及重启后完全独立；迁移旧数据不能随意归属到任一班。

### R3 · P1 · 桌面历史快照缺少核心数据

- 位置：`desktop/src/main/store.js:122`、137。
- 当前状态将班级、学生等十个集合分表保存，metadata 只存剩余字段；历史表直接复制 metadata，没有重建完整历史状态。
- 使用 Electron 自带 Node 运行实际 Store、写入临时 SQLite：最新状态能读到学生，上一版 history 却没有 classes 和 students 字段。
- 影响：历史表虽有版本号，不能据此还原完整的班级、名册和教学记录。这里不表示当前最新数据已丢失，也不表示手动导出 JSON 必然不完整。
- 验收：连续保存超过 20 版，修改/删除名册和教学记录后，从任一保留版本恢复到隔离库，所有核心集合及关联一致；模拟事务失败不得破坏当前数据；旧残缺快照须明确标识。

### R4 · P1 · 设置中的 AI 密钥绕过加密存储

- 位置：`app/src/app.js:955`；对应桌面渲染入口同样包含该处理逻辑。主进程虽有 safeStorage，实际设置提交把 key 放入 state.settings.ai，再调用普通保存。
- 合成密钥验证：设置处理结果保留明文 key，实际 Store 将其写入 metadata，后续保存又带入 history。
- 影响：与 PRD 的“Key 不进明文配置/日志”不一致。普通 JSON 导出默认会清空 key，本问题不能描述成所有导出必然泄露密钥。
- 验收：设置保存只使用主进程加密接口；业务状态不含 key；新旧 SQLite 主表与历史、导出文件、日志均通过合成密钥扫描；迁移需处理已有明文副本，不能仅修改新保存流程。

### R5 · P1 · AI 摘要把没有批改结果的听写算入学生成绩依据

- 位置：`app/src/app.js:608`，尤其 610 行。
- 筛选仅排除明确为“未录”的状态，缺失 studentMarks 时状态是 undefined，仍被计入。
- 复现：该班有一次听写，该生完全没有批改记录，生成的外发摘要却写“听写记录 1 次，累计错词 0 个”。
- 验收：无记录、未录、缺交、真实全对、已批有错分别建立固定样例；只有符合统计口径的结果计入；所有 AI 场景复用同一经过校验的数据摘要。

### R6 · P1 · 敏感记录仍参与外发 AI 统计

- 位置：`app/src/app.js:609`、613；界面 578 行承诺“敏感记录（仅本地，永不进入 AI）”。
- 复现：添加一条 sensitive=true 的“需关注”记录，外发摘要的观察记录数和需关注数随之改变。
- 本次验证未发现该函数发送观察记录正文或学生姓名；问题是敏感记录的存在与类别计数仍影响外发内容，应准确区分。
- 摘要/家长沟通生成处理直接调用 AI，未在这些处理路径发现发送前内容预览。
- 验收：添加、修改、删除任何敏感记录，外发 payload 应保持不变；用户可在发送前查看实际摘要；不使用真实学生记录进行外部接口测试。

### R7 · P2 · 档案“累计错词”只统计最后五次

- 位置：`app/src/app.js:563`、584。
- 同一个 dictHist 先 slice(-5)，再用于累计值和最近图表，累计标签与算法口径不一致。
- 验收：六次已批听写各错 1 词，累计应为 6；最近图表可以仅显示 5 次，且按日期排列。
- 本项为源码确认，尚未做真实页面交互复测。

## 建议的验收顺序

1. **数据正确性**：先修 R1–R6；覆盖两个班级、相同学号、未录/零分/缺考、删除与恢复。
2. **实际安装包**：从同一份最终源码重新构建，在安装版中完成录入→保存→退出→重启→导出→隔离恢复。当前存在安装包，只能证明产物存在，不能证明覆盖最新网页修改。
3. **教师完整任务**：教材定位→备课→课堂听写→纸面批改后录入→错词复练→学生档案；明确仍由教师人工批改及录入，不把“生成记录”描述成已向学生下发或自动批改。
4. **UI 与打印**：1366×768 和 200% 缩放、长名单滚动、弹窗焦点、多页 A4 与 PDF、课堂投屏、离线重启，全部在真实入口操作。
5. **内容和试用**：教材逐课核对、AI 固定样例评估，以及 PRD 的 ≥2 位教师 ×5 工作日试用。未见本次版本完整门禁证据前，不标记这些门禁通过。

功能数量已经较多，下一阶段优先把数据口径、恢复流程和真实教师任务做可靠。
