# 技术架构 v3 —— 桌面化重塑方案(Windows exe + macOS app)

> 2026-10-24。决策依据:产品两大命脉是 **A4 打印中心**(调研验证最充分集群)与**中文 TTS 听写报词**;同时要复用已打磨的欢快主题 Web UI(127KB 单页应用)、接入本地 SQLite 与 AI。候选:Electron / Tauri / Flutter / .NET MAUI / Python-Qt。

## 1. 选型结论

**Electron + TypeScript**(渲染层复用现有 Web UI)。

| 关键能力 | Electron | Tauri | 结论 |
|---|---|---|---|
| A4 打印/静默打印/PDF 导出 | `webContents.print()` / `printToPDF()` 跨平台官方支持 | **无官方打印支持**,社区插件仅 Windows(plugins-workspace #3340) | ✅ Electron 决定性 |
| 中文 TTS 报词(离线) | Web Speech API 走系统语音(Win: Huihui / mac: Tingting),开箱即用 | 依赖社区 crate `tauri-plugin-tts` | ✅ Electron |
| SQLite | better-sqlite3(同步、成熟) | rusqlite(需 Rust) | 平手(偏 Electron) |
| UI 复用 | 现有 127KB 单页应用近乎原样迁入 | 同样可复用 | 平手 |
| 包体积/内存 | ~100MB / 200-300MB | <10MB / 30-40MB | ⚠️ Tauri 优;教师办公机可接受 |
| 打包/自动更新 | electron-builder + electron-updater(久经考验) | NSIS/dmg + 内置更新器 | 平手 |
| AI 代理开发效率 | TS 全栈,迭代最快 | 需 Rust 工具链,原生调试摩擦大 | ✅ Electron |

**放弃项与理由**:Flutter/.NET MAUI = UI 全部重写且打印弱;Python-Qt = 打包脆弱;纯浏览器+本地服务(现 R1 形态)= 无法打包成真正的桌面应用,依赖用户默认浏览器。

## 2. 目标架构

```
┌────────────────────────── Electron 应用 ──────────────────────────┐
│ 渲染进程(现有 Web UI + TS 化)                                     │
│   欢快主题界面 · 打印中心预览 · 课堂模式 · AI 面板                  │
├──────── IPC(contextBridge,白名单 API)───────────────────────────┤
│ 主进程(Node/TS)                                                   │
│   ├─ store:SQLite(better-sqlite3,沿用 server.py 的表结构与校验)   │
│   ├─ print:A4 打印 / printToPDF 导出(打印中心专用)                 │
│   ├─ tts:speechSynthesis 桥接(语速/音色/队列)                      │
│   ├─ textbooks:教材 PDF 库与哈希清单                                │
│   ├─ ai-engine:AI 上下文引擎(见 PRD §AI)                           │
│   │    ├─ ContextBuilder:学生档案聚合 → 场景提示词                  │
│   │    ├─ 脱敏管线:姓名→代称、敏感记录过滤、发送摘要                 │
│   │    └─ Provider:DeepSeek/任意 OpenAI 兼容/本地 Ollama            │
│   └─ keychain:AI Key 经 safeStorage 加密存储                        │
└───────────────────────────────────────────────────────────────────┘
打包:electron-builder → Windows NSIS exe / macOS dmg;electron-updater 自动更新
数据:workbench.sqlite3(用户数据目录);教材 PDF 随包 resources/
```

## 3. 现有资产迁移映射

| 现有资产 | 去向 |
|---|---|
| 欢快主题 HTML/CSS(L0-L10 架构) | 渲染层原样迁入,CSS 不变 |
| app.js 状态与视图逻辑 | 渐进 TS 化;存储调用从 fetch(本地服务)改为 IPC |
| server.py 的表结构/校验/事务逻辑 | 移植为主进程 store 模块(逻辑 1:1,语言换 TS) |
| textbook 登记管线(register/build/哈希) | 主进程 textbooks 模块 |
| TTS 封装 | 渲染层 speechSynthesis(几乎不变) |
| AI 设置(DeepSeek 三件套) | 主进程 ai-engine + safeStorage |
| 12 册教材 PDF | resources/textbooks 随包 |

## 4. 风险

| 风险 | 对策 |
|---|---|
| better-sqlite3 原生模块与 Electron ABI | 使用 prebuild + electron-builder 重构建流程,CI 固定版本 |
| 包体积 ~120MB | 教师办公机可接受;已验证同类教育桌面软件先例 |
| Web Speech 音色因机器而异 | 听写设置页列出可用音色并试听;可选云端 TTS 升级 |
| 迁移期双形态(file:// 旧版) | 旧 R1 原型留档;首次启动提供"导入旧数据"向导 |
